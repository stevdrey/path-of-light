# Architecture and state

The prototype includes character components and control strategies, reusable collectibles/hazards, level scenes, menu settings and integration scripts. `GameProgress` separates attempt inventory from durable campaign facts. Settings persistence remains independent.

Attempt state includes health, score, diamonds, keys, position and visited checkpoints. Falls retain inventory; depletion/manual restart restore the level's entry inventory and full configured health. Level one starts empty; level two carries the earlier level's totals within a running playthrough. Reloading the application starts a fresh attempt; it never restores a saved key, damaged health or partially consumed scene.

The existing `recorded_secrets` (portal visits by level) and `completed_levels` are loaded once at menu startup or direct level entry and autosaved after portal entry and exit completion/celebration. `campaign_save.gd` validates versioned JSON, stages verified writes and retains a previous valid backup. Corruption can recover that backup; unusable or newer-version files are preserved and play continues in memory with a visible notice. See [ADR 0001](../adr/0001-campaign-state.md) and [campaign save evidence](../campaign-save-evidence.md) for the format, migration and limits. There is no map, attempt resume, reward album or approved expanded campaign in this change.

Returning to the menu and choosing **JUGAR**, or replaying after the final screen, starts another level-one playthrough while retaining durable facts. No current UI offers a destructive new campaign. `GameProgress.reset()` clears memory only for existing callers/tests; implementing a future fresh campaign requires an explicit persistent reset and backup policy. Gameplay retries use attempt-only methods and do not call this reset.

`GameSettings` persists three independent, default-off assists with audio/control preferences in `user://settings.cfg`. Live changes update heart capacity and checkpoint policy; no-fall-damage suppresses damage while retaining relocation. Changing frequency retains the attempt's last visited point. Settings never restrict campaign records, rewards or completion. See [ADR 0005](../adr/0005-configurable-assists.md).

Deferred retry/replay requests check their result. A failed retry rolls inventory back to the still-live scene and releases input locks; retry and pause remain available even while defeated. A failed final-screen replay retains completion and replay input. See [ADR 0004](../adr/0004-attempt-recovery.md) and [recovery evidence](../attempt-recovery-evidence.md) for the solo contract; ADR 0001 extends its session records to disk without changing recovery rules. Co-op ownership in ADR 0002 remains proposed.
