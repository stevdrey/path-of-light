# GitHub issue executive summary

Read the issue, implementing PR and actual verification results. Explain the player or project outcome, why it matters, what was delivered, evidence and known limitations in clear English. Distinguish automated checks from human playtests and identify untested platforms or accessibility claims. Do not invent counts, approvals or results. Post on the issue only if the user explicitly asks; otherwise provide a draft. Correct an existing summary rather than duplicating it.
